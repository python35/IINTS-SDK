# Claim Library

> [!tip] Use this before writing slides/docs
> A strong project is not just code. It is code plus claims that are precise, source-backed, and safe.

| Claim | Safe wording | Evidence / source | Limit |
| --- | --- | --- | --- |
| SDK purpose | IINTS is a pre-clinical SDK for simulation, validation, and reproducible review of insulin-algorithm ideas. | [[Sources by SDK Feature]], [[SDK User Home]] | not a treatment system |
| Metrics | IINTS reports TIR/TBR/TAR using language aligned with ADA/ATTD-style references. | [[ada_2026_glycemic_goals]], [[attd_2019_time_in_range]] | metrics are not clinical approval |
| Realism | IINTS compares traces with empirical realism envelopes from public/local T1D data packs. | [[Realism Reference Envelopes]], [[Dataset Source Library]] | realism check is a sanity check |
| Local AI | Local models can assist research workflows and summarize outputs. | [[Local AI and Hardware Sources]] | not autonomous dosing |
| Pump lab | Pico tooling packages bench-only artifacts and dry-run metadata. | [[Workflow - Pump Lab Bench Gate]], [[fda_infusion_pump_software_safety]] | no real insulin delivery |
| EUCYS impact | The project improves transparency and reproducibility for early insulin-algorithm research. | [[Evidence Claim Ladder]], [[EUCYS Jury Cockpit]] | not deployed medicine |

## Claim Formula

`What IINTS does` + `for whom` + `under what limit` + `where the evidence is`.
