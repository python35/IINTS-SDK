# EUCYS Model Companion

Build for the **IINTS-AF Model Companion** — a jury-facing reference handbook
covering the 16 registered formulas, their variables, behaviour, figures and
limitations. Produced in two editions from one source:

| Edition | Output | Purpose |
| --- | --- | --- |
| Web | `iints-af-model-companion.html` | Single file, filterable chapter index, mg/dL↔mmol/L converter. Published as an Artifact. |
| Print | `IINTS-AF-Model-Companion.pdf` | A4, 83 pp, contents with real page numbers, PDF bookmarks, running footer. |

## Build

```bash
./make_all.sh              # figures + fonts + web + pdf
./make_all.sh --no-figs    # skip the simulation runs (they take a few minutes)
```

Environment overrides: `IINTS_PY` (SDK virtualenv python, needed for the
figures), `CHROME_BIN` (any Chromium; otherwise a puppeteer-cached Chrome for
Testing is discovered automatically).

## How it fits together

```
make_figures.py   runs the real SDK and writes figures/*.svg
fetch_fonts.py    downloads the 3 webfonts once -> src/91_fonts.css (data URIs)
build.py          src/*.html + figures -> the web edition
build_pdf.py      the same sources + src/90_print.css -> the print edition
render_pdf.mjs    headless Chrome over CDP -> PDF
read_outline.py   reads the PDF outline -> chapter page numbers
make_pdf.sh       the two-pass PDF build
```

## Why it is built this way

**Every figure is generated by executing the SDK.** `make_figures.py` imports
the real model code — `smooth_threshold_excess`, `HovorkaPatientModel`,
`SensorModel`, `PumpModel`, `glycemic_risk`, the `Simulator` — so no curve in
the document is illustrative. A figure changes when the model changes.

**The PDF is a two-pass build.** Pass 1 establishes pagination; the PDF outline
Chrome generates is read back to map each chapter to its page; pass 2 rebuilds
the contents list with those numbers. The page-number slot is fixed-width, so
filling it cannot reflow the contents and invalidate the numbers. `make_pdf.sh`
prints both page counts — if they differ, the numbers are stale.

**Fonts are embedded as data URIs.** Headless Chrome does not reliably reach
Google Fonts, and when it fails the entire document renders in fallback faces
with nothing to indicate it. `render_pdf.mjs` additionally asserts
`document.fonts.check()` for all three families and exits non-zero otherwise.

**The renderer asserts what a checker cannot see.** Three guards exist because
each of these failed silently at least once:

- images decoded before printing — `loading="lazy"` never fires in a paged
  render, so every figure printed as an empty plate;
- no zero-sized figures;
- MathJax signalled ready before printing.

**Print stylesheet order matters.** `90_print.css` is injected immediately
before `<div class="shell">` so it comes after every other stylesheet.
Anchoring it to the first `</style>` puts it ahead of the main sheet — which
silently loses every print rule, visible only as a changed page count.

## Editing content

Chapters live in `src/02_*.html` … `src/09_*.html`. Each is a
`<section class="chapter">` carrying `id`, `data-part`, `data-n` and
`data-title`; the web index, the PDF contents and the bookmarks are all
generated from those attributes, so adding a chapter needs no other change.

Sub-labels use `<h4 class="sub">`; the print build rewrites them to `div` so
they do not each become a PDF bookmark.

## Provenance

Content is grounded in `src/iints/core/formula_registry.py` (16 formulas with
LaTeX, units, literature and evidence class), the patient backends, the device
models and `core/safety/config.py`. Defaults quoted in the handbook are read
from those sources; the evidence-class chips mirror the registry's own labels.

Research and educational software. Not a medical device.
