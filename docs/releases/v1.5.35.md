# v1.5.35

Release `v1.5.35` adds a 3D digital-twin viewer to the desktop workbench, corrects cohort-comparability issues in the multi-source training pipeline, tightens statistical rigor for the EUCYS evidence suite, and clears the type-checker and minimal-install CI gaps found while preparing this release.

## Desktop Workbench: 3D Virtual Patient Digital Twin

- Adds a WebGL 3D view of the simulated patient alongside the existing 2D compartment diagram, built on the same `compartment_timeline` data (no new backend endpoint).
- Renders five organ sites (gut, subcutaneous pump depot, plasma/vascular, periphery, and a liver node) as glass-like meshes sized by their live compartment values; the liver has no dedicated ODE state in the Hovorka model, so it is fed by the live endogenous-glucose-production flux instead and is labeled as a source, not a stored compartment.
- Animates four particle streams (carbohydrate absorption, insulin appearance, peripheral glucose uptake, endogenous glucose production) whose density, speed, and direction track the schema's own live flux values.
- Adds a 0-1440 minute scrubber with playback and speed control, and clickable organs/flux markers that show the model's actual rate expression and current value.
- Colors the vascular organ red below 70 mg/dL, using the same canonical plasma-glucose column the rest of the desktop app already treats as ground truth.
- Scoped to the Hovorka model for this release; Bergman support (which has no dedicated peripheral-tissue compartment) is a later iteration.
- Vendors three.js as a single local, unmodified file, since the desktop app has no bundler and a strict content-security policy with no import map.

## Cohort Comparability (Multi-Source Training Data)

- Flags constant ISF/ICR fallback values per row instead of silently mixing them with HUPA-UCM's real per-subject estimates.
- Flags OhioT1DM glucose samples produced by grid interpolation, separately from real sensor readings.
- Labels `insulin_units`' differing physical meaning per source dataset (a sparse bolus/basal event vs. a densely-filled basal-rate expansion), so it is no longer pooled as if it meant the same thing everywhere.
- Adds a per-subject sample weight when blending datasets, so one oversized subject (HUPA0027P was 53.4% of its cohort) no longer dominates a blended training batch; the blend manifest now warns when any subject exceeds 30% of its source.
- Flags OhioT1DM's de-identification date-shift explicitly, and adds a per-subject relative time axis to HUPA-UCM to match the other cohorts.

## Statistical Rigor (EUCYS Evidence Suite)

- Adds cluster-aware confidence intervals (naive, cluster-t, and hierarchical bootstrap) for the fully-crossed EUCYS study design, so repeated runs on the same virtual-patient profile are no longer treated as independent samples.
- Adds a Clarke Error Grid implementation that only ever computes zone percentages from real paired reference/prediction data; there is no code path that produces a zone percentage without measurements to back it.
- Adds a rate-aware prediction-accuracy analysis alongside Clarke, since Clarke grades measurement error, not forecast error, and cannot by itself catch a numerically-close prediction that points the wrong clinical direction.
- Consolidates LBGI/HBGI/BGRI (Kovatchev risk-space transforms) into one canonical implementation that `iints.core.clinical_metrics` and `iints.analysis.diabetes_metrics` both delegate to, removing the possibility of two disagreeing definitions of the same published index.

## CI and Type Checking

- Fixes `mypy src/iints/` to 0 errors (was 46): pandas `.values` typed as `ndarray | ExtensionArray` replaced with `.to_numpy(dtype=float)`, a proper `TypedDict` for the CGMacros benchmark participant table, and several other narrow type-correctness fixes with no behavior change.
- Fixes the minimal-install CI job (`pytest tests/ -q` with no `torch`/`pyarrow` installed), which previously failed 13 unrelated test files with collection errors because one unguarded torch import took down the whole `iints.research` package on import. Torch and pyarrow are now consistently treated as the optional extras `pyproject.toml` already declares them to be.

## Compatibility

- Python: `3.10` through `3.14`.
- Desktop beta: `0.2.9`.
- No changes to on-disk data formats, MDMP envelopes, or public CLI commands.

IINTS-AF remains a research and educational system. This release does not provide clinical validation, regulatory certification, or treatment functionality.
